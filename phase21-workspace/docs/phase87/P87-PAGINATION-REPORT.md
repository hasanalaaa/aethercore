## Delivered behavior

Request optional snapshot_cursor tag3 distinguishes legacy absence from present-empty initial snapshot. Response optional next_snapshot_cursor tag7 and reload_required tag8 are additive; existing integer tags and meanings remain unchanged. Bindings are generated by the repository contracts build.rs/prost generator. No dependencies or oneof variants were added.

The service holds immutable owner-scoped bounded Timeline values behind random UUIDv4 tokens (existing UUID RNG), with 32 global cursor entries and an absolute five-minute TTL checked on lookup and insertion. Continuations inherit the original creation time; issuing pages does not renew TTL. Oldest issued entries are evicted at capacity. Unknown/tampered, expired/evicted, another-owner, or post-restart tokens receive a typed reload with no entries/digest/cursor. Such rejection is not published as a live page. Legacy integer reads remain fresh/uncached. Retained history is the existing bounded recent window, not an archive.

UI supports legacy servers with absent cursors, admits only the current renderer request/session/reset generation, preserves pinned pages when new live history arrives, and declares localized new-activity/explicit refresh. This includes activity arriving while an older page RPC is pending. Reconnect and reset invalidate browsing and delayed replies. Refresh starts a new snapshot; changed legacy-history digest forces reload rather than merging inconsistent pages. Initial unpinned live history remains visible. EN/AR older/loading/reload/activity messages use owned catalogs.

Care navigation hook: selectTimelineEntry(sourceId: string): boolean in apps/ui/src/features/timeline/controller.ts. It selects only an exact source_id already loaded, clears missing selection, and is invalidated with the owner/session. Timeline rows expose data-source-id, outline the selection, and focus/scroll after tick with a stale-selection guard. Care callers can setPage('activity'), await loadTimeline(), then selectTimelineEntry(`care-run:${runId}`) or `execution:${planId}`; false means entry not loaded, with no search or fabricated match.
