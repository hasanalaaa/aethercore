# AetherCore Zenith Recursive Issue Ledger

This ledger records findings from the recursive adversarial pass against the delivered Zenith source tree. It is additive to the historical `ZENITH_ISSUE_LEDGER.md`; a PASS in an older gate is not treated as proof against a later finding.

| ID | Component | Severity | Root cause | Failure scenario | Implemented correction | Verification | State |
|---|---|---:|---|---|---|---|---|
| ZR-001 | `operation-engine` / consent | High | Immutable plan JSON was hashed, but duplicated SQLite presentation columns were not required to agree with the hashed material. | Storage corruption can make consent show a changed title/risk/time/identity while the digest still describes different frozen actions. | Verify ID/title/risk/created/owner equality after digest parse; reject impossible update time; render `PlanView` from verified material. | `duplicated_plan_columns_cannot_diverge_from_hashed_material`; recursive source gate. | FIXED |
| ZR-002 | `operation-kernel::EventBus` | Medium | Per-owner replay streams had no retirement policy. | Long service uptime across Windows logon churn retains stale replay queues indefinitely. | `MAX_OWNER_STREAMS=128`, monotonic activity tick, oldest-inactive eviction only; never evict live subscribers; stale cursors reset/hydrate. | Two EventBus regressions + recursive gate. | FIXED |
| ZR-003 | `update-engine::UpdateCoordinator` | Medium | Per-owner update snapshots/release maps were retained forever. | Historical principals accumulate update metadata for the process lifetime. | `MAX_OWNER_STATE_CACHE=128`; evict oldest quiescent state only; staging/staged/consent/install states are non-evictable. | Two update retention regressions + recursive gate. | FIXED |
| ZR-004 | Maintenance service request admission | High | Request cap was per session only while native request workers can outlive a disconnected session. | Reconnect churn around non-cooperative native calls can accumulate detached worker threads. | Process-global atomic RAII worker budget (`MAX_GLOBAL_INFLIGHT_REQUESTS=64`); typed Busy/503 on exhaustion. | Atomic saturation unit regression + recursive gate; Windows stress remains mandatory. | FIXED |
| ZR-005 | Mutation authority lifetime | High | `MutationLease` was held by the telemetry/status watcher instead of the actual mutation worker. | Watcher creation/failure/early termination can release machine-wide single-flight authority while privileged work still executes, or retain authority after work is done. | Exact lease identity (`workload + plan + owner`); remove unleased mutation starts; hand the lease into driver/repair/cleanup/startup workers; watchers are observation-only. | Kernel identity regression + route/worker structural gates + Windows execution tests. | FIXED |
| ZR-006 | Mutation worker failure handling | High | Several detached worker starts assumed `thread::spawn` succeeds; repair/cleanup worker errors could be separated from authoritative failure cleanup. | OS thread exhaustion after consent can strand a plan in a non-terminal state or panic a request path. | Named fallible `thread::Builder`; spawn failure journals/fails safely, clears running/telemetry state; repair/cleanup worker errors explicitly call durable failure transitions. | Recursive gate + targeted Windows worker-failure tests. | FIXED |
| ZR-007 | Service support-thread creation | Medium | Session, event-pump, and request workers used panic-oriented spawn semantics; request cancellation registration precedes worker creation. | Thread creation failure can leak session accounting/cancellation IDs or terminate the serving path abruptly. | Fallible named thread creation; restore session count; fail event-pump setup; remove cancellation registration and return typed Busy/503 on request-worker failure. | Recursive source gate + request admission regression. | FIXED |
| ZR-008 | Read budget lifetime | Medium/High | Expensive read `ReadBudgetLease` was held by polling watchers rather than the collector worker. | Watcher lifetime can diverge from WUA/WMI/PnP/filesystem collection, violating per-kind/global read budget assumptions. | Exact `ReadBudgetLease::matches`; remove unbudgeted scan/assessment starts; lease moves into driver/repair/cleanup/startup/diagnostics worker; production routes use leased entry points. | Kernel identity regression + route/worker structural gates. | FIXED |
| ZR-009 | Streaming watcher resilience | Medium | Watcher thread creation could panic after backend work had already begun. | Request can fail after work starts, while no watcher publishes progress. | Central fallible named `spawn_watcher`; watcher failure is logged and reconnect hydration remains recovery path. | Recursive source gate. | FIXED |
| ZR-010 | Runtime support threads | Medium | Desktop reconnect, IPC client reader, and repair pipe-reader threads did not uniformly fail explicitly. | OS thread creation failure can panic setup or leave child/IPC lifecycle ambiguous. | Fallible named threads; desktop setup returns error, IPC connect returns typed I/O error, repair kills/waits child and joins surviving readers on setup/timeout failure. | Recursive source gate; native Windows fault injection required. | FIXED |
| ZR-011 | Fluid press interaction | Medium | Press state still carried a fixed-duration CSS transition; pointer cancellation did not explicitly fence possible later click activation. | Feedback can lag direct manipulation and abnormal cancellation can leave activation ambiguity. | Remove fixed press transition; preserve presentation-value spring; arm one-shot click fence on cancel/lost capture. | TypeScript check + deterministic motion tests + recursive gate. | FIXED |
| ZR-012 | Coordinator public API boundary | High architecture | Production routes used leased methods, but legacy public `start` / `start_scan` / `start_assessment` methods still allowed future callers to bypass mutation/read admission. | A new internal consumer can accidentally execute privileged mutation or expensive collection without the global supervisor/budget. | Remove all public unleased entry points; make private worker boundaries require non-optional concrete leases; migrate tests to leased APIs. | Recursive API-surface/mandatory-lease gates; Windows workspace compile/tests. | FIXED |
| ZR-013 | IPC synchronous I/O teardown | High availability / Medium security | Bounded writer queues isolated producers, but teardown did not actively cancel a writer blocked in synchronous named-pipe I/O; reader and writer lifetimes were not cross-coupled. | A hostile/non-reading peer can pin a transport thread after queue saturation or disconnect; the opposite direction may remain blocked as well. | Open a least-rights real thread handle, request `CancelSynchronousIo` on shutdown/backpressure/disconnect, cross-cancel reader/writer directions, bind the server reader to its session worker, fence client pump writes after shutdown, and avoid holding the registry mutex across the Win32 call. | Recursive structural gates + client/server saturation regressions; qualified Windows slow-peer/service-stop fault injection remains mandatory. | FIXED / NATIVE QUALIFICATION PENDING |
| ZR-014 | IPC production endpoint authentication | High security | A client-side PID pin had been considered, but the documented `GetNamedPipeServerProcessId` contract is for a server handle created by `CreateNamedPipe`; relying on it from a `CreateFile` client would make the trust proof depend on unsupported behavior. | A local pipe squatter could otherwise receive the first protocol bytes unless the connected kernel object itself is authenticated before `ClientHello`. | Production clients open with `READ_CONTROL`, verify the connected pipe object's owner SID equals the resolved `NT SERVICE\AetherCoreMaintenance` service SID, and require the registered `AetherCoreMaintenance` service to be running as an own-process service before any frame is sent. Debug builds use a separate strict 128-bit per-launch rendezvous name rather than weakening production verification. | Recursive source gates; `verify-ipc-pipe-security.ps1` verifies the live kernel owner/DACL plus installed service account/type on Windows. | FIXED / NATIVE QUALIFICATION PENDING |
| ZR-015 | IPC namespace squatting / startup ownership | High security / availability | A fixed named-pipe namespace is first-creator sensitive; retrying identity failure can also hide a hostile endpoint behind later valid instances. | A standard-user process races service startup, becomes creator, or keeps a competing endpoint present while clients retry. | The service claims startup with `FILE_FLAG_FIRST_PIPE_INSTANCE`; only pipe-open absence is retried. Once any endpoint opens, production identity failure is terminal before `ClientHello`. Debug console mode uses a fresh 128-bit pipe suffix and is compiled out of release behavior. | Recursive first-instance/retry-order gates; Windows pre-squat/startup collision and service-restart tests remain mandatory. | FIXED / NATIVE QUALIFICATION PENDING |
| ZR-016 | Named-pipe server-instance authorization | High security | Granting Authenticated Users generic write on a named pipe also grants the bit used as `FILE_CREATE_PIPE_INSTANCE`. | An authenticated local user can create an additional server instance in the trusted pipe object and potentially receive client connections. | Replace `GRGW` with exact `FILE_READ_DATA | FILE_WRITE_DATA | READ_CONTROL | SYNCHRONIZE` (`0x00120003`) for Authenticated Users; production clients request the same specific mask via `OpenOptionsExt::access_mode`. Bit `0x4` is absent by construction. | Rust regression `authenticated_client_access_cannot_create_pipe_instances`; recursive DACL/mask gates; native DACL probe in enterprise stress. | FIXED / NATIVE QUALIFICATION PENDING |
| ZR-017 | Named-pipe server impersonation of desktop client | High security | Without an explicit client SQOS, a pipe server can receive a stronger default impersonation level than the desktop needs for authorization. | A compromised or squatted server attempts to use the desktop user's token to access local resources on the user's behalf. | Every production client open sets `SECURITY_IDENTIFICATION` through `OpenOptionsExt::security_qos_flags`, preserving identity/group inspection for service authorization while denying resource impersonation/delegation. The native probe uses the same SQOS. | Rust SQOS regression + recursive source gate + Windows native pipe-security probe. | FIXED / NATIVE QUALIFICATION PENDING |
| ZR-018 | IPC namespace continuity across session churn | High availability / security defense | Startup used FIRST_INSTANCE, but the sequential accept loop did not explicitly prove that a service-owned pipe instance existed continuously between a rapidly disconnected session and creation of the next listener. | A hostile local process repeatedly connects/disconnects and races a zero-instance gap to become first creator, causing namespace preemption/DoS even though production clients would reject the hostile owner. | Split unconnected listener ownership from connected sessions. Claim startup with `PipeServerListener::claim_first`; after every accept create `create_successor()` synchronously before session admission/handoff; after accept failure reclaim with FIRST_INSTANCE; successor-creation failure stops fail-closed. | Recursive ordering/reclaim regressions; Windows rapid connect/disconnect + squatter race and service-stop tests. | FIXED / NATIVE QUALIFICATION PENDING |
| ZR-019 | Named-pipe open retry classification | Medium security / availability | The client retry loop treated every pipe-open error as transient. | Access-denied, invalid-access, or configuration/security drift can be masked as ordinary startup latency, delaying a fail-closed diagnosis and repeatedly touching an invalid endpoint state. | Retry only `ERROR_FILE_NOT_FOUND` and `ERROR_PIPE_BUSY`; return every other open failure immediately; retain terminal `UntrustedPeer` after a successful open. | Rust regression `pipe_open_retry_policy_retries_only_absence_or_busy_conditions` + recursive retry-policy gates. | FIXED |
| ZR-020 | Machine-wide mutation arbitration | High security / availability | A predictable `Global\AetherCore.WindowsUpdateMutation.v1` mutex could be pre-created, and `CreateMutexW(..., TRUE, ...)` does not acquire an already-existing mutex merely because the call returns a handle. | A standard user or stale object can deny mutation availability or make acquisition semantics diverge from the intended single-flight contract. | Replace the named mutex with an installer-provisioned `%ProgramData%\AetherCore\state\machine-mutation.lock`; runtime opens `OPEN_EXISTING` with reparse protection and takes a fail-immediate exclusive byte-range `LockFileEx`. Installer hardens the file to SYSTEM/Administrators/service SID; all five mutators share the guard. | Recursive source gates; installer ACL + overlapping-lock contention probe. | FIXED / NATIVE QUALIFICATION PENDING |
| ZR-021 | Named-pipe service-SID authority | High security / availability | The production pipe granted broad SYSTEM/Administrator server authority instead of binding namespace ownership to the exact maintenance-service identity. | Another broadly privileged local principal could be authorized to create a competing server instance, weakening least privilege and endpoint identity. | Resolve and success-cache `NT SERVICE\AetherCoreMaintenance` through a bounded, aligned SID buffer; validate the returned SID with `IsValidSid`; generate production SDDL with owner = service SID, service SID = sole `GENERIC_ALL` server authority, AU = exact `0x00120003`; remove SYSTEM/Admin server ACEs. Native probe requires service-SID owner/create-instance, no Admin allow, exact AU mask and protected exact ACE shape. | Rust descriptor regression; recursive gate; `verify-ipc-pipe-security.ps1` installed-service evidence. | FIXED / NATIVE QUALIFICATION PENDING |
| ZR-022 | Maintenance service SID mode / mutation compatibility | High correctness / security architecture | A write-restricted service token is a poor fit for a maintenance engine that must modify Windows and third-party resources whose ACLs cannot safely be rewritten to include the AetherCore service SID. | `SERVICE_SID_TYPE_RESTRICTED` can turn legitimate registry/service/filesystem/WUA/driver mutations into access-denied failures while creating a misleading impression that LocalSystem has been sandboxed without proving every mutation surface. | Configure `SERVICE_SID_TYPE_UNRESTRICTED`: retain the service-specific SID as an enabled-by-default, owner-capable ACL identity for AetherCore-owned resources and the named pipe, but do not add restricting SIDs to the LocalSystem token. Add a live process-token probe requiring the service SID exactly once, `SE_GROUP_ENABLED_BY_DEFAULT` + `SE_GROUP_OWNER`, and zero restricting SIDs. Typed IPC, immutable consent, MutationSupervisor and product-resource ACLs remain the primary containment controls. | Recursive policy gates; `verify-maintenance-service-token.ps1`; installer verification; qualified Windows mutation matrix. | FIXED / NATIVE QUALIFICATION PENDING |
| ZR-G01 | Recursive audit integrity | Medium governance | Token checks alone can remain true in syntactically malformed source. | A patch can duplicate a Rust declaration or a private method while expected audit tokens still exist, producing a false structural PASS. | Meta-regression rejects repeated public declarations and duplicate top-level method names within the same `impl`, and pins the corrected diagnostic refresh signature. | `zenith-recursive-audit.py` meta-gates after endpoint-authentication, service-SID, ACL/SQOS and evidence-policy hardening. | FIXED |
| ZR-G02 | Native IPC evidence strictness | Medium/High governance | The first native DACL probe checked that AU contained required rights and lacked create-instance, but did not reject unrelated extra allow rights, AU deny drift, unprotected DACL inheritance, unexpected allow trustees, or ACE encodings the probe does not understand. | A widened installed ACL could still produce a green evidence artifact even though it no longer matched the source security policy. | Require exact AU allow mask `0x00120003`, zero AU deny mask, protected DACL, no unexpected allow trustees, and no unparsed ACE types; preserve explicit create-instance offender detection and emit the stricter fields in evidence. | Recursive probe-policy regressions + Windows execution of `verify-ipc-pipe-security.ps1`. | FIXED / NATIVE EXECUTION PENDING |
| ZR-R01 | Named-pipe cancellation proof / overlapped decision | Medium residual | The transport still uses synchronous named-pipe I/O, so `CancelSynchronousIo` timing and the final pre-syscall race cannot be proven by source inspection. | Under hostile timing a write may begin immediately around a cancellation request; OS/provider behavior must be measured before declaring deterministic teardown. | Source now requests cross-thread cancellation and fences post-shutdown queued writes. Keep overlapped I/O as a conditional migration, not an assumed requirement. | Windows slow-peer, disconnect, service-stop, repeated-cancel, thread/handle leak and soak evidence required. | OPEN QUALIFICATION |
| ZR-R02 | Dependency freeze | Release blocker | Delivered source has no approved `Cargo.lock` / `pnpm-lock.yaml`. | `--locked` reproducible/signable release cannot be proven. | Keep trusted freeze workflow fail-closed; do not fabricate lockfiles in this pass. | `freeze-dependencies.ps1 -Refresh`, review, then `-VerifyOnly`. | OPEN PREREQUISITE |
